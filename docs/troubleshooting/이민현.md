# 트러블슈팅 — 이민현 (팀원 1 · 공통 · 인증 · 운영)

## 알림을 읽어도 계속 '안 읽음'으로 보임 (2026-11-12, R · 알림 / 통합 점검)
- 문제: 알림 종에서 읽은 알림도 굵은 글씨(안 읽음)로 남았다. 화면은 `isRead`를 읽는데, 알림 목록 API는 `read`라는 키로 보내고 있었다
- 원인: boolean 필드 이름을 `isRead`로 지으면 Lombok이 getter를 `isRead()`로 만들고, Jackson은 `is`를 떼고 속성 이름을 `read`로 본다. 같이 보니 SSE 알림 본문은 문자열로 직접 만들어서 `createdAt`이 빠지고, 메시지에 따옴표가 있으면 JSON이 깨졌다
- 해결: 필드는 `read`, JSON 이름은 `@JsonProperty("isRead")`로 고정했다. SSE 본문도 같은 DTO를 Spring이 JSON으로 바꾸게 해서 목록 한 건과 모양을 맞췄다. 키는 테스트(`NotificationResponseDTOTest`)로 묶었다 (#83, decisions.md 11-12)
- 배운 점: boolean 필드에 `is`를 붙이지 않는다. 화면과 약속한 JSON 키는 눈으로 보지 말고 테스트로 고정한다

## IDE에서 실행할 때만 나는 매개변수 이름 오류 (2026-11-12, H · 개발 환경)
- 문제: STS에서 서버를 실행하면 관리자 대시보드가 `IllegalArgumentException: Name for argument of type ... not specified`로 실패했다. 같은 코드가 Gradle · CI에서는 정상이었다
- 원인: Spring은 `@RequestParam` · `@PathVariable`에 이름을 적지 않으면 컴파일된 매개변수 이름(`-parameters`)을 읽는다. Gradle(Spring Boot 플러그인)은 이 옵션을 켜지만 STS(Eclipse 컴파일러)는 기본값이 꺼져 있어 클래스 파일에 이름이 없다
- 해결: 그 화면은 팀원 3이 `name = "from"`처럼 이름을 적어 바로 고쳤다(#80). 원인을 찾아 보니 이름 없이 쓴 곳이 수십 곳이라, 코드 대신 IDE 설정을 맞추기로 했다 — STS 'Store information about method parameters' 켜기, IntelliJ는 Gradle로 빌드 · 실행 (#88)
- 배운 점: "CI에서는 되는데 내 PC에서만 안 된다"면 코드보다 빌드 도구 차이(컴파일 옵션)를 먼저 본다. 같은 조건을 맞추려고 CI는 로컬과 같은 MariaDB · 설정 파일로 돌린다

## 대시보드 날짜가 하루 앞당겨질 수 있음 (2026-11-06, T · 대시보드)
- 문제: 일별 통계 기간(최근 14일)을 `new Date().toISOString()`으로 만들면 한국 시간 오전 0~9시에는 어제 날짜가 나와서 오늘이 기간에서 빠진다
- 원인: `toISOString()`은 UTC 기준이라 한국(UTC+9)보다 9시간 늦다
- 해결: 브라우저 지역 날짜(`getFullYear` · `getMonth` · `getDate`)로 `YYYY-MM-DD`를 만들고(`toDateParam`), 기준일은 서버가 Asia/Seoul `LocalDate`로 정한다 (#47)
- 배운 점: 날짜만 보낼 때는 `toISOString()`을 쓰지 않는다. 서버 · DB · JDBC 시간대를 Asia/Seoul로 맞춘 비기능 요구사항이 화면에서도 지켜지는지 본다

## 리뷰를 동시에 두 번 쓰면 500 (2026-11-12, Q · 리뷰 / 통합 점검)
- 문제: 같은 배송에 두 탭에서 동시에 리뷰를 저장하면 하나는 409가 아니라 500이 났다
- 원인: '이미 리뷰가 있는지' 검사와 저장 사이에 다른 요청이 끼어들면, 마지막에 DB 유니크 키(`shipment_id`)가 막으면서 `DataIntegrityViolationException`이 그대로 500이 됐다
- 해결: 저장할 때 그 예외를 잡아 검사와 같은 `REVIEW_EXISTS`(409)로 돌려준다. 앞의 검사는 빠른 길이고, 유니크 키가 마지막 방어선이다 (#91)
- 배운 점: '확인하고 저장'은 동시 요청에 뚫릴 수 있다. 중복을 막아야 하는 곳은 DB 제약을 두고, 그 예외를 사용자가 이해하는 응답으로 바꾼다

## 권한 점검에서 403 대신 400이 나온 17곳 (2026-11-19, W · 테스트)
- 문제: API 80개를 역할 4개(고객 · 기사 · 관리자 · 토큰 없음)로 불러 보니, 권한이 없는 역할에게 17곳이 403이 아니라 400(입력 오류)을 돌려줬다
- 원인: Spring MVC는 컨트롤러 메서드의 인자를 만들면서 `@Valid` 입력 검사를 먼저 하고, `@PreAuthorize`는 그다음 메서드를 부를 때 검사한다. 그래서 빈 본문을 보내면 권한 검사 전에 400이 난다
- 해결: 형식이 맞는 본문으로 다시 보내 17곳 모두 403인 것을 확인했다(뚫린 곳 없음). 권한 규칙을 SecurityConfig에 한 번 더 적으면 같은 규칙을 두 곳에서 관리해야 해서 그대로 두었다
- 배운 점: 권한 점검은 '형식이 맞는 요청'으로 해야 정확하다. 400이 보안 구멍은 아니지만 막힌 사람에게도 입력 규칙 문구는 보인다

## SSE 구독이 가끔 500 · 탭 두 개면 알림이 번갈아 끊김 (2026-11-23, R · 알림 / 팀원 4 몫 대신)
- 문제: develop에서 화면을 열면 브라우저 콘솔에 SSE 구독(`/api/notifications/subscribe`) 500이 가끔 보였다. 같은 회원이 탭을 두 개 열면 알림이 한쪽에만 오고 연결이 번갈아 끊겼다
- 원인: 서버가 회원당 연결을 하나(`Map<Long, SseEmitter>`)만 들고 있어서 새 구독이 오면 이전 연결을 닫았다. 개발 모드(React StrictMode)는 화면을 두 번 붙여 구독이 거의 동시에 2번 들어오는데, 두 번째 구독이 첫 연결을 닫은 직후 첫 요청이 그 닫힌 연결로 첫 메시지를 보내다 `IllegalStateException` → 500이 됐다
- 해결: 회원당 연결을 탭마다 여러 개(최대 5개)로 들고, 보내다 실패한 연결만 뺀다. heartbeat도 어떤 예외에도 멈추지 않게 했다 (#139, `NotificationServiceImplTest` 7개)
- 배운 점: 개발 모드의 "두 번 실행"은 실제 사용자의 탭 여러 개 · 새로고침을 미리 보여 준다. 연결을 사용자당 하나로 가정하지 않는다

## 공통 Modal을 열면 화면이 깨짐 (2026-11-23, K · 프론트 공통 / 팀원 4 몫 대신)
- 문제: `components/common/Modal`을 쓰면 여는 순간 React 오류로 화면이 깨져서, 화면마다 확인 창을 직접 만들어 쓰고 있었다 (기사 관리 #110, 회원 관리)
- 원인: `createPortal`에 넣을 곳(두 번째 인자 `document.body`)을 주지 않았다. 게다가 창이 어두운 배경 `div` 안이 아니라 옆에 있어서, 오류를 고쳐도 배경에 가려지고 창을 누르면 배경 클릭으로 닫히는 구조였다
- 해결: 창을 배경 안에 넣어 `document.body`로 띄우고, 배경 · Esc로 닫히되 창 안을 눌러서는 안 닫히게 했다. 그 뒤 회원 관리 · 리뷰 창 · 기사 관리 창 4개를 공통 Modal로 바꿨다 (#141 · #146 · #147)
- 배운 점: 공통 컴포넌트는 만든 사람이 한 번이라도 화면에 띄워 봐야 한다. 쓰는 곳이 0개인 공통 컴포넌트는 고장 나 있어도 아무도 모른다

## 헤더 알림 창이 헤더 높이에서 잘림 (2026-11-23, X · UI 다듬기)
- 문제: 알림 종을 누르면 창의 "알림" 제목만 보이고 아래가 잘렸다. 알림 창 코드는 바뀐 적이 없었다
- 원인: 좁은 화면에서 헤더가 넘치지 않게 헤더 안쪽 상자에 `overflow-x-auto`를 넣었는데(#124), CSS는 한 방향만 스크롤로 만들어도 다른 방향(`overflow-y`)이 `visible`이 아니라 `auto`가 된다. 그래서 그 안에서 `absolute`로 띄운 알림 창이 헤더 높이에서 잘렸다
- 해결: 바깥 상자의 가로 스크롤을 빼고 좁은 화면은 줄바꿈(`flex-wrap`), 메뉴만 가로 스크롤하게 했다. 휴대폰 폭에서는 알림 창이 화면 밖으로 나가서 화면 양옆 16px 안에 고정했다 (#145)
- 배운 점: 드롭다운 · 툴팁이 뜨는 상자에는 `overflow`를 걸지 않는다 (꼭 걸어야 하면 창을 portal로 밖에 띄운다). 레이아웃을 바꾸면 그 안에서 뜨는 창도 같이 열어 본다
