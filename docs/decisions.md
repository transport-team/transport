# 결정 기록

팀이 정한 것을 한 줄씩 남긴다. "왜 이렇게 했지?" 논쟁을 줄이고 발표 자료가 된다.

| 날짜 | 결정 | 이유 |
|---|---|---|
| 2026-11-02 | Spring Boot 4.1.2 · Java 21로 통일 | 팀원 전원 JDK 21, 최신 버전 지원 기간이 김. 수업 코드는 구조만 참고 | 교수님 코드와 비교 · Boot 4는 Security 7 · Jackson 3 등이 바뀌어 예제 호환 문제 |
| 2026-11-02 | 저장소는 backend/ · frontend/를 담은 모노레포 | 도메인별로 백엔드 · 프론트를 한 PR에서 함께 수정 |
| 2026-11-02 | DB는 각자 로컬(Docker MariaDB), 시드는 data.sql로 공유 | 공용 DB는 ddl-auto 변경 · 데이터 충돌로 서로를 깨뜨림 |
| 2026-11-02 | 결제는 토스페이먼츠 테스트 키 · 결제창(API 개별 연동 키) | 계약 없이 테스트 가능, 실제 결제 없음 |
| 2026-11-02 | 배송 상태에 결제대기(PENDING_PAYMENT) 추가 | 결제 전 신청서 저장 · 금액 검증 · 30분 자동 취소 |
| 2026-11-02 | 배포는 HTTPS 필수, 1차 배포 8주차 | 브라우저 위치 API는 HTTPS · localhost에서만 동작 |
| 2026-11-03 | 자바 · gradle 들여쓰기는 탭 (.editorconfig) | 기존 자바 파일 대부분이 탭, IDE 재정렬로 파일 전체가 바뀌는 충돌 방지 |
| 2026-11-03 | 서비스는 interface + Impl (수업 방식), 비밀번호 8자 이상 | 수업 코드와 같은 구조로 설명 · 리뷰가 쉬움 |
| 2026-11-03 | 로그인은 JSON API(`POST /api/auth/login`) + JWT, 수업의 formLogin은 쓰지 않음 | React 화면 · api.md 명세와 맞춤, 서버 세션 없음 |
| 2026-11-03 | 토큰: 액세스 30분 · 리프레시 1일, 재발급 때 둘 다 새로 발급 | 사용 중 끊김을 줄이고 리프레시 토큰을 오래 쓰지 않게 |
| 2026-11-03 | 권한 전환일 전까지 토큰 없는 요청은 통과, 잘못되거나 만료된 토큰만 401 | 로그인 기능이 들어가도 팀원 개발 · 테스트가 깨지지 않게 |
| 2026-11-03 | 팀원 2 부재 중에는 기사 가입 · 로그인에 필요한 `DriverService` 최소 구현을 팀원 1이 작성 (복귀 후 인계) | 기사 가입 · 로그인 일정을 미루지 않기 위해 |
| 2026-11-03 | 기사 로그인: 승인 대기(PENDING) → 403 DRIVER_NOT_APPROVED, 중지(INACTIVE) → 403 ACCOUNT_DISABLED | 승인 여부는 `Member.enabled`가 아니라 `Driver.status`로 판단 (enabled는 관리자 계정 비활성화용) |
| 2026-11-09 | 권한 전환: 공개 API(api.md 권한 "전체") 외에는 로그인 필요. `/api/admin/**` ADMIN · `/api/driver/**` DRIVER는 URL 규칙, 그 밖의 역할은 컨트롤러 `@PreAuthorize` | 공통 파일(SecurityConfig)을 API마다 고치지 않고 역할 검사는 각 도메인에서. 11-03의 "토큰 없는 요청 통과"는 이날로 끝 |
| 2026-11-05 | 약관은 내용을 고치지 않고 새 버전으로 개정(새 버전 사용 중 · 이전 버전 사용 중지). 같은 이름은 하나만 사용 중, 삭제는 동의한 회원이 없을 때만, 가입 화면은 필수 먼저 → 등록 순. 개정해도 기존 회원에게 다시 동의를 받지 않음(공지로 안내) | 동의 이력(term_agreement)이 약관 행을 가리켜서, 내용을 덮어쓰면 회원이 무엇에 동의했는지 사라짐. 재동의는 로그인 흐름까지 바뀌어 이번 범위 밖 |
| 2026-11-06 | 대시보드 숫자 기준: 접수 = 결제 완료(PAID), 날짜는 `paidAt`. 매출 = PAID 결제 금액 합계(환불돼 CANCELED가 된 결제는 빠짐). 배차 대기 = 지금 REQUESTED, 진행 중 = 지금 ASSIGNED · PICKED_UP · IN_TRANSIT · ARRIVED. 일별 통계는 최대 92일. 대시보드용 읽기 전용 집계 메서드는 팀원 1이 팀원 3 Service에 추가하고 팀원 3이 리뷰 | status.md에서 결제 완료가 곧 접수(REQUESTED)라 접수 시각 = 결제 시각. 배송에는 완료 시각이 없어 오늘 완료는 2단계(상태 이력 집계). 월 정산(U)은 완료 기준이라 대시보드 매출과 다를 수 있음. 집계 메서드를 기다리면 T가 막혀서 "내 도메인 파일만" 규칙의 예외로 기록 |
| 2026-11-06 | 보안 점검: 로그인 실패 횟수 제한(계정 잠금 · 지연)은 이번 범위 밖. 토큰 쿠키는 `sameSite: strict`, HTTPS에서만 `secure` | 학습 프로젝트 범위 · 일정. 로그인 실패 문구는 이메일 · 비밀번호를 구분하지 않아 가입 여부를 덜 드러내고, 비밀번호는 BCrypt. 배포 뒤 필요하면 Nginx 요청 수 제한으로 보완 |
| 2026-11-06 | 배차 방식: **기사 지원 → 고객 선택** (1안, 팀 결정). 고객이 운송 요청 등록(기사 지정 없음) → 기사가 요청 목록에서 가능한 건에 지원 → 고객이 지원한 기사 중 선택 · 거절 → 선택된 기사로 배차 확정 · 알림. 고객이 기사 한 명을 지정하고 기사가 확정 · 거절(5분 미응답)하는 2안은 채택하지 않음. 요구사항 ADM-04(관리자 후보 추천 · 배정) 대신 CUS-08 · DRV-08, status.md 배차 전이의 주체는 고객 | 2안은 거절 · 미응답 때마다 고객이 다시 요청해야 해서 확정까지 오래 걸림. 1안은 #48로 구현을 시작함 |
